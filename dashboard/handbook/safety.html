Safety and trust

How Nexus Memory protects what it stores, and how you can tell good information from bad.

Protection against poisoned memories

Imagine someone slips a wrong note into a filing cabinet, and that note happens to sit exactly where everyone looks first. That is "poisoning": misleading entries that sound plausible and rank high in search. Nexus has several layers against that.

The strongest layer is the two-lane search. Nexus never relies on meaning alone. It always runs two searches side by side: one by keyword (exact words, hard to fool), one by meaning (flexible, but easier to mislead). The results are then merged. A poisoned entry would need to be both topically exact and semantically perfect to rise to the top. That is very hard to fake.

Source trust adds another layer. Every memory carries a note of where it came from:

🟢 Your agents and youslightly boosted
🟡 Curated external materialneutral
🔴 Uncurated, unknown originslightly demoted

Material of unknown origin can never outrank what you or your agents personally confirmed.

Trust and contradiction handling

Memories change over time. The newest statement is not automatically the truest one. Nexus tracks every important fact as a "belief" with a trust value and a status:

  • Active the statement stands as is.
  • Contested something contradicts it; both versions are kept visible, nothing silently replaced.
  • Retracted it was withdrawn (by you, or because a better source corrected it).

When statements clash, a fixed ranking decides, roughly: a withdrawal beats an override, an override beats a confirmation, a confirmation beats an objection. No automatic "last write wins", no silent edits.

Good to know: Nothing is deleted in this process. Old versions remain visible and searchable, so you can always reconstruct how a piece of knowledge changed.

Guardrails: when memory protects your machine

Nexus does not only store knowledge, it can also enforce it. You (or your agent) can save a rule like "never delete the folder X". From then on, whenever an agent wants to run a destructive command (delete a folder, drop a database, kill a process), Nexus checks that command against your stored rules and blocks it when it would hit a protected target.

Three properties make this trustworthy in practice:

  • It fails closed: if the protection rules cannot be read, destructive actions are blocked, not waved through.
  • An override is possible, but only with an explicit reason that is stored for later review.
  • Guardrails never accidentally paralyze everyday work: when the memory service itself is unreachable, the check steps aside and lets normal work continue.

What stays private

Every memory carries one of three access levels: public (all your agents), trusted (approved agents only), private (you alone). Private entries never leave your machine, and backups of the memory store are written so that only your user account can read them. See the full page: Who can see what.

Self-cleaning

Memory needs hygiene. SICA, the built-in caretaker, scans regularly for expired short-term notes, low-confidence entries and contradictions. Expired throw-away notes get removed automatically, everything else is never deleted without review. Contradiction groups can be turned into one clean summary. You can run a check anytime from the dashboard (Health button) or just let it run on its schedule.
