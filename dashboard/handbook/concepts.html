The building blocks

Every part of Nexus Memory, explained like to a friend. No blueprints — just what it does for you and when you should touch it.

🗄️ Qdrant — the archive

The database where all memories live. It never sends anything anywhere; it just stores and finds. You never need to configure it in daily use. The only interesting number for you: the memory count on the dashboard (should grow slowly and steadily).

🏷️ Memory categories — what kind of thing it is

Every memory has a category, and the category controls its lifespan and treatment:

CategoryForLifespan
factstable truths ("the NAS is at 192.168.31.40")forever
rulestanding instructions ("never delete X")forever
preferencehow you like things ("concise answers")forever
procedurehow-to knowledge (workflows)forever
sessionwhat happened in one work session7 days, then cleaned
tempscratch notes, pointers1 day, then cleaned

Anything not marked disposable stays forever. Missing timestamps are never deleted.

🔄 SICA — the self-cleaning crew

SICA is a routine that periodically walks through all memories and fixes what it can on its own: it deletes expired temp and session memories, spots contradictions (same thing, two different statements) and merges duplicate entities. Everything else becomes a suggestion for you to review — SICA never silently destroys real content. You can run it from the dashboard at any time; it also runs on its own schedule.

🛡️ Guardrails — the bodyguard

Guardrails protect your system from your own agents. Before a destructive action (delete files, wipe a database, kill processes), the agent must check Nexus for stored protection rules. If you once stored "Never delete ~/my-projects/", every agent using Nexus will be blocked from deleting it — automatically, on every machine that shares this memory.

The safety logic: if protection rules can't be read, destructive actions are blocked (never waved through). If Nexus itself is unreachable, guardrails step aside so they never block normal work by accident. Overrides need a written reason and are stored for audit.

⛽ Fuel — the tank station for memory AI

Old memories need sorting and condensing — that's work for an AI. Fuel is the rule for which AI does it and what it may cost:

StationCostNeeds
1. Local Ollamafreenothing — if you have Ollama running
2. OpenRouterpenniesyour existing OPENROUTER_API_KEY
3. Other keyspenniesOpenAI / Nous / custom keys you already have

Nexus tries stations in order (cheapest first) and skips closed ones automatically. Nothing to configure if you have any one of these running.

The switch on the dashboard: ON = old memories get summarized & sorted automatically, spending against a hard $5/month cap (checked before every single paid call — it can never overrun). OFF = nothing leaves your machine, memories stay unsorted; everything else still works. When to use OFF: if you have no Ollama and no keys, or you simply want zero external calls. When ON makes sense: you want the auto-sorting and accept a few cents a month.

🧬 Facts that never lie twice

If a new fact contradicts an old one, the old one isn't silently overwritten — it is marked "superseded" and the new one becomes the current truth. A chain stays visible: what was believed when, what replaced it. No zombie facts, no silent rewrites.

🕸️ The knowledge graph

Related memories connect themselves (no manual linking). That's what powers the Graph view in the dashboard: clusters of your knowledge, isolated orphans, and the paths between facts. Purely informational — nothing to configure.
